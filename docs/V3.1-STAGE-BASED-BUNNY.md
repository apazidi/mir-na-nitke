# Мир на ниточке — v3.1: Stage-based Bunny Slice

**Дата:** 3 ноября 2026  
**Статус:** утверждённое направление для следующего прототипа; реализация ещё не выполнена.  
**Платформа:** Web / Telegram Mini App (тестируем через GitHub Pages).  
**Главная цель:** подготовить красивый, понятный idle + clicker с одним кроликом, который можно дать на тест рукодельнице.

> **Решение v3.1:** отказываемся от анимации каждой петли. Игровая сцена использует 8 согласованных качественных состояний изделия. Клик/idle увеличивают прогресс; при достижении порога состояние сменяется. Крючок переносится в нижний action bar, а не «работает» в основной иллюстрации.

## 1. Продуктовая гипотеза

Красивые, физически понятные **крупные этапы изготовления игрушки** дадут больше эмоциональной ценности, чем технически сложная симуляция отдельных стежков.

Проверяем три вещи:
1. Игроку сразу нравится изображение, хочется его рассматривать.
2. Понятно, что клики и idle приближают следующую стадию.
3. После готового кролика хочется увидеть следующий предмет / композицию.

**Это игра, а не учебник вязания.** Не заставляем игрока считать петли, выбирать узоры, соединять детали вручную или двигать крючком по экрану.

## 2. Сценарий: 8 художественных состояний

**Единая схема:** статичный уютный рабочий стол с фиксированным ракурсом; состояния меняются только у центральной композиции. «Подготовленные детали» лежат рядом на столе. Не изображать невозможное «вырастание» головы из туловища: отдельно связанная деталь появляется в лотке, а затем происходит сборка.

| № | При достижении прогресса | Что видно на центральной сцене | Микронаграда |
| --- | ---: | --- | --- |
| **00** | 0% | Начальное кольцо пряжи на столе, рядом клубок | Первый визуальный зацеп |
| **01** | 12% | Небольшая открытая чашечка туловища, видны настоящие ряды | «Туловище начато» |
| **02** | 28% | Готовое объёмное туловище, рядом клубок | «Туловище готово» |
| **03** | 44% | Отдельная готовая голова лежит рядом с туловищем | «Голова готова» |
| **04** | 60% | Рядом лежат два ушка, отличимых от головы | «Ушки готовы» |
| **05** | 73% | Добавлены четыре лапки и хвостик, всё ещё отдельные части | «Все детали готовы» |
| **06** | 86% | Кролик собран, но мордочка ещё не вышита | «Почти готово!» |
| **07** | 100% | Готовый кролик с глазами, носиком и лёгким румянцем | «Знакомься — твой кролик!» |

**После 100%** — отдельная короткая сцена: готовый кролик оказывается на фетровой полянке и один раз моргает/шевелит ушами. Это не девятая стадия вязания, а награда за завершение.

Проценты — **демонстрационная прогрессия**, окончательно настраивается через конфиг. Важнее красивый ритм, чем точность продолжительности работы над реальной игрушкой.

### Почему именно так

Этапы различаются **силуэтом и смыслом**, а не только процентом видимости. Их легко производить и тестировать. В будущем тот же механизм работает для цветка, дерева, домика и других предметов.

## 3. Визуальная композиция / Screen spec

**Mobile-first:** опорный viewport 390×844 CSS px, ширина 360–430 CSS px; desktop сохраняет ту же игровую сцену в центральной колонке.

**A. Шапка (≈10%)**
- Название: «Кроличья полянка».
- Текущая цель: «Вяжем кролика».
- Компактный общий прогресс.

**B. Главная сцена (≈55–60%)**
- Качественная иллюстрация рабочего стола: лен, фетр, мягкий тёплый свет.
- В центре — текущая стадия кролика.
- Текстильные детали и клубок — декоративное окружение.
- **Никаких активных крючков, летящих петель, масок по краю вязания и обязательных кликов по самой картинке.**
- Вся сцена переключает художественное состояние только на границах стадий.

**C. Action bar (≈12–15%)**
- Один большой тактильный элемент: **[иконка крючка] ВЯЗАТЬ**.
- Подпись: «+N петель за касание».
- При нажатии: лёгкий press-scale, пульсация и короткое «+N» рядом с кнопкой; визуальная реакция ≤150 мс.
- Полоса прогресса/маленький индикатор «до следующего открытия» рядом с кнопкой или над ней.
- Кнопка активна даже если игрок нажимает быстро; анимации не должны блокировать события.

**D. Нижняя панель (≈15–20%)**
- Две компактные модернизации: «Крючок» (эффект клика), «Клубочек» (idle).
- Не перегружать сцену ресурсами и декоративными карточками.
- При необходимости панель прокручивается, но action bar остаётся доступен.

**Важно:** для игрушек амигуруми корректный инструмент — **крючок**, не спицы. Иконка крючка в action bar; в сюжетном изображении рабочий инструмент можно не показывать.

## 4. Художественный контракт и файлы

Опираемся на ранее утверждённый «golden frame»: premium cozy handcrafted textile diorama, реальная фактура пряжи, кремовая палитра, фетр, мягкие тени. Главная сцена должна выглядеть красиво **даже без чисел и UI**.

### Система исходников

- **Один master** на все восемь состояний: единые ракурс, свет, размеры и поза предметов.
- Идеально: редактируемая 2.5D/3D композиция с переключаемыми слоями деталей. Допустима согласованная послойная иллюстрация.
- **Не генерировать восемь состояний независимо.** AI — для концепции, текстур, отдельных референсов; окончательная последовательность — из контролируемого исходника.
- Каждый этап — **полная композиция подготовленных деталей на прозрачном фоне**, привязанная к общей системе координат. Рабочий фон не меняется.
- Персонаж в состоянии 07 и на полянке должен быть тем же кроликом. Финальная сцена может повторно использовать его рендер + отдельные глаза/уши для микроанимации.

## 5. Логика idle + clicker

Один источник истины: общее количество заработанных «петель» / work points. Из него вычисляются процент и стадия. Отдельное ручное состояние стадии не сохранять — оно производное.

- Click: одно нажатие добавляет N work points. Нажатия не требуют попасть по картинке.
- Idle: фиксированное число work points в секунду плюс улучшения. Время вне приложения начисляется при следующем входе (cap: 8 часов на первом тесте).
- Клик/idle **не меняют пиксели внутри стадии**; меняют счётчики и заполняют прогресс-бар.
- При прохождении порога — атомарная замена stage-изображения, короткий bounce у карточки/«готово»; **при 100%** — завершение, полянка и анимация оживания.
- Когда игрок возвращается из офлайна и пересёк 2+ стадии — сразу показать актуальную стадию и короткое резюме («За это время готовы голова и ушки»); не запускать длинную очередь переходов.
- Улучшения пока только два, цены/множители берём из прототипа и настраиваем конфигом.
- Сохранение: work, coins, clickLevel, idleLevel, lastSeenAt, completionShown. Отдельный ключ для v3.1, чтобы не путать состояние с v2/v3-spike; сохранять после покупок/кликов и по жизненному циклу страницы.
- После финала не начислять бесконечные петли. Показать законченную композицию и опцию «Пройти ещё раз» в режиме тестирования. Следующий предмет пока не реализуем.

### Ритм игры / два режима

**Обычный режим:** первый переход быстро (ориентир — 15–30 секунд активной игры). Далее стадии растягиваются, чтобы появились причины вернуться после паузы. Числа после тестирования настроить, не прибивать к сценам.

**Demo-тест:** отдельный режим, активируемый только через параметр URL (например, ?demo=1), чтобы пройти **весь цикл за 3–5 минут**. Отдельное сохранение для demo, чтобы тест не портил обычный прогресс. Индикатор «Демо» виден, ускоренный idle/клик настройками.

**Работа с кодом**:
1. Взять из v3-spike расчёт idle, click, покупок, офлайн-прогресса и обработку сохранений.
2. Удалить canvas-механику рядов, привязку working-point, движение нитки, крючок внутри изображения.
3. Вместо draw-row ввести stageFromProgress(progress) и image preload/cache.
4. В HTML рабочей сцены показывать композицию из постоянного фона + одного текущего stage-изображения (CSS absolute layers или drawImage).
5. Убрать pointerdown по сцене. Повесить tap только на нижний action bar (кнопка, keyboard-accessible). Дебаунс кликов не нужен, но ограничить частоту косметических эффектов.
6. На 100% включить состояние FINISHED → MEADOW и скромную микроанимацию.
7. Поставить автоматические тесты на пороги, быстрые клики, офлайн-переход через несколько порогов, покупку и перезапуск.
8. Держать флаг demo и кнопку «сбросить тест» вне основного игрового интерфейса.

**Правило интеграции:** если художественные картинки ещё не согласованы, не подменять их прежними процедурными рядами. Можно использовать строгие временные заглушки в локальной dev-сборке, но тест с рукодельницей — только на утверждённом арте.

## 7. Acceptance criteria / Definition of Done

### Визуал
- [ ] 8 стадий из единой художественной системы, без скачков цвета, размеров и ракурса.
- [ ] В каждом кадре пряжа выглядит объёмной и естественной.
- [ ] Состояния узнаваемо отличаются, не воспринимаются как части одной проявляющейся фотографии.
- [ ] Основная сцена выглядит уютно и без UI.
- [ ] Нет артефактов масок, неровной обрезки и «склеек» поверх кролика.
- [ ] Финальный кролик и кролик на полянке — один персонаж.

### Игра
- [ ] Клик ощущается сразу; основная сцена не является кликабельной.
- [ ] Прогресс внутри стадии понятен; переключение стадии доставляет небольшую награду.
- [ ] Idle, покупки, офлайн-прогресс и сохранения работают.
- [ ] После офлайна не показывается неактуальная стадия.
- [ ] Полянка и оживание появляются один раз, без двойной награды.
- [ ] Все стадии быстро доступны в demo для 3–5-минутного теста.
- [ ] На мобильном экране не перекрыты изображение и action bar.

### Тест с рукодельницей
Без объяснений дать игру на телефоне и спросить:
1. «Похожи ли стадии на реальный процесс изготовления амигуруми?»
2. «Какая стадия выглядит неправдоподобно?»
3. «Было ли приятно открывать следующую картинку?»
4. «Хочется ли связать цветок или домик после кролика?»

**Условие передачи:** даём игру на этот тест, когда и арт, и полный цикл готовы. Одна красивая обложка без законченного кролика — не v3.1.

## 8. Порядок работ / Gates

**Gate A — art-first (обязательный):** утвердить stage-00, stage-02, stage-06 и stage-07 в общей композиции. Три-четыре разных этапа нужны, чтобы проверить художественную непрерывность и способность держать стиль. Если всё выглядит цельно, делать остальные.

**Gate B — полный набор 8 состояний:** экспорт с одинаковыми anchor/pivot + фон и финальная полянка.

**Gate C — переключение картинок + UI:** собрать чистую mobile-first сцену, нижний action bar и плавную, но короткую UI-обратную связь.

**Gate D — экономика и финал:** перенести сохранение, idle, покупки, demo; полянка, оживание, smoke-tests.

**Gate E — первый пользовательский тест:** показать готовую v3.1 рукодельнице и собрать замечания. Только после этого переходить к нескольким композициям и долгосрочной прогрессии.

**Самый важный вывод:** в игре продаётся не симуляция петель, а удовольствие от превращения набора ниток в симпатичный, живой мир.
