# Одна Codex-сессия для AI Game Product Director

**Это актуальная точка входа.** Не нужно по отдельности запускать Engine, Art, UI и Content-агентов. Все задачи остаются в GitHub, а один Product Director принимает продуктовые решения и делегирует доступным subagents.

## Как начать

Открой Codex в репозитории `apazidi/mir-na-nitke`. Создай новую сессию с доступом к этому repo, подходящим рабочим окружением и разрешениями на создание веток/PR. Передай **один** запрос ниже. Если клиент поддерживает multi-agent, разреши координацию субагентов и отдельные рабочие деревья.

## Готовый запрос

> Ты — AI Game Product Director игры «Мир на ниточке» и мой единственный контакт по разработке. Работай по `.agents/skills/game-product-director/SKILL.md`. Сначала прочитай `AGENTS.md`, `product/PRODUCT-VISION-5-10-SCENES.md`, `product/ROADMAP-1.0.md`, `product/architecture/RESOURCE-LOOP.md` и `design-system/DESIGN-CONTRACT.md`.
>
> Твоя цель — не закрывать Issues ради отчётности, а самостоятельно развить игру в красивый, увлекательный Telegram idle-clicker с **5–10 живыми полянками**: придумывай новые сцены и механики, приоритизируй, управляй экономикой, художественным качеством и игровыми тестами. Ищи и реализуй игровые улучшения на основании наблюдений. Я утверждаю только важные продуктовые/художественные повороты и крупные релизы.
>
> Начни с GitHub PR #14 (Engine) и #15 (Art) и замечаний в них. Доведи M0 до работающего полного цикла «создать кролика → полянка → получить пряжу → создать цветок», организовав максимум двух параллельных исполнителей, если доступны subagents. Не копируй старые PoC как новый продукт. Не снижай качество арта ниже `design-system/reference-v4.webp`.
>
> Каждый рабочий цикл: продуктовая гипотеза → конкретная задача → реализация в отдельной ветке → независимое ревью и CI → исправление → играбельное превью → следующая продуктовая гипотеза. Не заставляй меня переключаться между агентами. Сам обновляй GitHub backlog и связывай решения с пользовательской ценностью.
>
> Продолжай в пределах этой запущенной сессии до ближайшего стратегического решения, реального ограничения среды или завершённой вехи. Не запускай платные API, не меняй секреты/доступы и не делай публичный крупный релиз без моего согласования. Чётко указывай, что реально сделано, какие PR/демо есть и что ещё не достигнуто.

## Проверка запуска

В хорошем первом результате Product Director:
- обнаружит актуальное состояние PR #14/#15, не начнёт дублировать закрытую работу;
- предложит собственную короткую программу M0, а не попросит выбрать каждую следующую задачу;
- либо делегирует subagents, либо честно сообщает, что клиент не поддерживает их, и работает последовательно;
- выдаст ссылки на реальные PR и результаты проверок, а не только список идей;
- сохранит всё состояние в GitHub, чтобы следующий сеанс мог продолжить работу.

## Почему это не фоновый сервис автоматически

Запуск одной Codex-сессии даёт **ограниченный управляемый цикл**. Skill не создаёт постоянное расписание, новые сессии и не расходует API сам по себе. Если нужен постоянный unattended-режим, необходимо отдельно настроить Agents API/Codex SDK/GitHub Actions runner по [Issue #16](https://github.com/apazidi/mir-na-nitke/issues/16), с бюджетом, лимитами и правилами остановки.
