## Контракт

- `config.defaultCraftAuto?: boolean`: только свежий state; отсутствие означает прежнее `true`. `state.craftAuto` и `view.craftAuto` явно сохраняют выбор. Старый save без поля читается как `true`, даже если новый fresh default выключен.
- `dispatch({type:'setCraftAuto', enabled:boolean, now})` сначала учитывает прежний интервал, затем меняет режим и начинает новый интервал accrual. Пауза выключает автоматическую работу проекта; ручной клик, доход, взаимодействия, события и воспоминания продолжают работать. `view.rates.idle` остаётся потенциальной скоростью, у paused project `etaSeconds=null`.
- `config.recraftableIds?: string[]`, `view.projects[].canRecraft`, `startRecraft(itemId)` и `cancelRecraft`. Повтор требует owned + allowlist и пустой project; содержит `project.recraft:true`. Он наследует текущий auto, не тратит пряжу, не снимает оригинальное размещение. Завершение/отмена не добавляют owned, placement, доход или событие. Обычное течение мира сохраняется. Отмена настоящего проекта этим действием запрещена.
- Старые item/recipe вне allowlist остаются обычными полноценными проектами; allowlist ограничивает только бесплатный повтор. Параметры темпа, стартовый кошелёк и условия улучшений задаются внешним config, в core не зашиты.

## Импорт между конфигурациями

`migrateConfigState(state, fromConfig, toConfig, now)` валидирует источник, учитывает время по прежней конфигурации, сохраняет заработанный мир и авто, переносит долю item/recipe work на новый бюджет и сбрасывает accrual к уже полученным wallet/work. Затем результат проверяется в новой конфигурации. Нельзя использовать helper повторно с прежним `fromConfig` для уже перенесённого состояния.

В `createSession` новый opt-in: `{key: NEW_KEY, legacyKey: OLD_KEY, legacyConfig: oldGameplayConfig, legacyMigration:'config'}`. Старый путь по умолчанию `legacyMigration:'v1'` сохранён для исторического v2-key → v3-key перехода. Номер внутренней схемы state остаётся `2`; имена v3/v4 относятся к ключам и игровым конфигурациям.

Импорт читает старый ключ только при отсутствии нового. Любое существующее значение нового ключа, включая пустое/повреждённое, препятствует импорту. Старый raw никогда не записывается. Ошибка миграции включает временную игру без записи обоих ключей; несостоявшийся импорт также не показывает away-report с незачисленными наградами. Write failure сохраняет прежнее поведение временной открытой сессии и уведомления; перенос в другую вкладку/между устройствами не добавлялся.
