# Ресурсная петля: мастерская ↔ полянки

**Статус:** продуктовый контракт для нового 1.0 PoC; **ещё не реализован в движке и валидаторе**.
**Принцип:** кликать приятно и осмысленно в ОБОИХ режимах. Мастерская создаёт предметы, полянки производят ресурсы для новых проектов.

## 1. Главная петля

1. Игрок начинает с небольшого количества **волшебной пряжи** — ресурса `yarn`. Начального запаса достаточно, чтобы создать первого кролика и не попасть в тупик.
2. В **мастерской** игрок выбирает проект, инвестирует пряжу в него и ускоряет его изготовление кликом. Idle делает ту же работу автоматически. 4–8 художественных стадий сменяются целиком — не симулируем настоящие петли.
3. Завершённый кролик появляется на **полянке**. Он не только украшает её, но и приносит небольшое количество волшебной пряжи в фоновом режиме.
4. На полянке игрок гладит/чешет кролика; короткая анимация даёт **бонусные ниточки**. После открытия цветка кролик иногда нюхает его — новое фоновое событие и бонус.
5. Накопленные ресурсы тратятся на **следующий проект** и улучшения мастерской. Следующие предметы и полянки раскрывают новые сочетания/доходы.

**Формула:** `создаём → размещаем → общаемся/наблюдаем → собираем ресурсы → создаём снова`.

## 2. Два независимых вида прогресса (не путать!)

| Сущность | Зачем | Как начисляется |
| --- | --- | --- |
| `yarn` (волшебная пряжа) | Единый тратимый ресурс: запуск проектов и улучшения | Базовый стартовый запас + пассивное производство полянки + бонусные взаимодействия |
| `work` (очки работы) | Прогресс текущего изделия 0–100% | Idle мастерской и клик на кнопке «Вязать» |

Игровые очки работы **не являются реальным числом петель**, как и ресурс `yarn` не означает физически измеренную массу пряжи.

Для PoC пряжа резервируется/тратится **при запуске** проекта, а не на каждом нажатии; работа может продолжаться после этого без ресурса. Таким образом не возникает ситуации, когда игрок увлёкся кликами, исчерпал пряжу и не может довязать текущий предмет.

## 3. Что делает игрок на двух экранах

### Мастерская
- Выбрать проект из доступных; увидеть стоимость пряжи и будущую пользу.
- Нажимать на крупную кнопку «Вязать» для ускорения **work**, либо наблюдать idle-прогресс.
- Покупать улучшения idle/клика за `yarn`.
- После 100% получить красивую финальную стадию и отправить изделие на одну из предусмотренных позиций полянки.

### Полянка
- Готовые персонажи живут, слегка двигаются и дают **пассивный доход**, даже если полянка сейчас не открыта.
- Игрок может **взаимодействовать** с активными объектами. «Погладить кролика» = короткая отзывчивая анимация + ограниченный бонус пряжи.
- Несколько готовых предметов дают **комбинированные события**. Например, `rabbit + flower → sniff → bonus yarn`.
- После создания другой полянки все готовые полянки продолжают пассивную работу. Не заставляем обходить их ежедневно только ради сбора дохода.

Два режима должны быть связанными, но **ни один не должен становиться обязательной рутиной**.

## 4. Простая экономическая защита от «softlock» и гри́нда

- **Начало:** фиксированный стартовый запас `yarn` гарантированно покрывает стартовый проект. Не требуем ресурса от ещё не существующего кролика.
- **Базовый приток:** после завершения первого изделия появляется хотя бы один источник пассивной пряжи. При желании — малый резервный источник от стартового клубочка, чтобы восстановиться после неудачных покупок.
- **Взаимодействия:** бонусный клик даёт быстрый результат, но имеет мягкое ограничение (например, небольшой cooldown/запас внимания) для предотвращения бесконечного фарма; начальные числа — гипотезы, не баланс.
- **Idle:** не теряем накопленное при закрытии; общая экономическая модель считает все открытые полянки через timestamp. Ограничение офлайна — глобальная настройка, не свойство каждого предмета.
- **Мультиполянки:** производство суммируется, но удорожание проектов и апгрейдов должно ограничивать экспоненциальное ускорение.
- **UX:** смена полянки не требует нажать «Собрать» на каждом объекте. Активные взаимодействия интересны как дополнительный бонус.

## 5. Контентные агенты: декларативные награды, без нового JS

Существующий `product/architecture/CONTENT-CONTRACT.md` уже поддерживает `interactions` с действиями `pet`, `sniff`, `idle` и зависимостями от слотов. Предлагается **расширение контракта v2**, не ломающее существующие `schemaVersion: 1` и черновые примеры.

Пример **целевого формата** (пока НЕ поддержан валидатором):

```json
{
  "economy": {
    "passive": [
      {"id":"rabbit-yarn","requires":["rabbit"],"resource":"yarn","ratePerHour":20}
    ]
  },
  "interactions": [
    {
      "id":"pet-rabbit",
      "requires":["rabbit"],
      "actorSlot":"rabbit",
      "action":"pet",
      "reward":{"resource":"yarn","amount":3,"cooldownSeconds":20}
    },
    {
      "id":"rabbit-sniffs-flower",
      "requires":["rabbit","flower"],
      "actorSlot":"rabbit",
      "action":"sniff",
      "trigger":"idle",
      "reward":{"resource":"yarn","amount":8,"cooldownSeconds":600}
    }
  ]
}
```

Поля `reward`, `trigger`, `economy.passive` и `ratePerHour` — **предлагаемое расширение**. До изменения валидатора, engine API и тестов агент не должен добавлять их в `ready` пакеты как будто они работают.

### Разделение ответственности

- **Engine:** кошелёк `yarn`, `work`, детерминированный начислитель idle, ограничения бонусов, транзакции, сохранение, анти-дублирование, реакция UI.
- **UI / Skin:** кнопки «Вязать», «Погладить», эффекты пряжи, статусы и всплывающие награды. Динамические суммы рисуются живым текстом.
- **Item pack:** арт и стадии предмета, `workUnits`, предлагаемый `yarnCost`, итоговый спрайт. Не содержит собственного игрового кода.
- **Meadow pack:** требования слотов, рецепты взаимодействий, рекомендуемые ресурсы/награды. Допустим только whitelist действий, без произвольного JavaScript.
- **Validation/CI:** проверки существования resource IDs, числовых границ, допустимых действий, зависимости от готовых предметов и отсутствие недостижимого первого источника ресурса.

Для новых ресурсов/действий сначала отдельная задача на движок, затем агенты используют новый контракт без правок общих модулей.

## 6. PoC для проверки нового цикла — только два экрана

**Контент:** один кролик, один цветок и одна полянка. Не обязательно строить второй мир сразу.

**Старт:** клубочек выдаёт достаточную пряжу для кролика.
1. В мастерской создать кролика (idle + клик + смена красивых 8 стадий).
2. Разместить на полянке; включить пассивную пряжу.
3. Погладить кролика → короткая анимация → +yarn в общем кошельке.
4. Вернуться в мастерскую и за пряжу создать цветок.
5. Разместить цветок → открыть совместное idle-событие «кролик нюхает цветок» → дополнительный доход.
6. Закрыть игру, вернуться: ресурсы и работа начислены без двойных наград. Сохранение работает при переходах и перезагрузке.

**Definition of Done:**
- [ ] Можно пройти весь цикл без вмешательства разработчика и без использования тестового ползунка.
- [ ] Нет тупика по ресурсам до создания первого источника.
- [ ] Оба экрана имеют осмысленное действие клика и idle-прогресс.
- [ ] Полученный в полянке ресурс реально меняет доступность новых проектов в мастерской.
- [ ] Взаимодействие с кроликом даёт визуально понятный бонус, без требования спама.
- [ ] Цветок включает новое поведение и доход, но не требует новой логики в коде двигателя.
- [ ] Выход/вход и смена полянок не дублируют начисления.
- [ ] Арт соответствует утверждённому качеству; красивая сцена не подменяется плоскими UI-заглушками.

## 7. Куда это ведёт

- **Кролик + цветок:** нюхает, появляется пряжа.
- **Кролик + домик:** отдыхает, повышая пассивный доход.
- **Птица + дерево:** поёт, даёт периодическую награду.
- **Кот + клубок:** играет с ним — активная реакция и небольшой бонус.

Это иллюстративные механики; каждое новое взаимодействие создаёт контентный агент через JSON и арт, а движок исполняет общий набор действий.

**Приоритет:** после базового GameShell реализовать именно этот ресурсный круг до выпуска нескольких полянок. Он связывает весь мир в экономическую систему, а не оставляет полянки декоративными галереями.
